01 · 产品契约

主要使用者
你自己，业余星空摄影爱好者 Windows 电脑为主；手机端后续扩展
触发时刻
深空与星野作品散落各处 深空成图带水印、原始帧在机身；星野只有成片与视频
核心任务
把已有作品整理归档并持续增量 深空按目标、星野按银河/星轨/延时，两条线分开管
完成标志
点开一个目标就能看全 拍过几次 · 累计曝光 · 哪版最好 · 这是什么天体；星野则看记录卡与作品时间线
一句话定义：一个「档案管理 + 自动整理 + 天体科普」的桌面工具。它不修图、不叠加、不控制赤道仪；价值在于让作品找得回、看得懂、算得清、拿得出手。全库只分两条主线：深空（目标导向，Dwarf 拍摄）与星野（银河 / 星轨 / 延时，含视频）。

DWARF_DARK机身内置暗场库545 帧 · 2.1 GB
RESTACKED机身内重新叠加的输出2 组（M42 拼图、IC434）
Solving_Failed解析失败时的诊断截图297 张 png，无科研价值

单个会话里有什么

  • shotsInfo.json：目标名、RA/DEC、单帧曝光、增益、滤镜、CMOS 温度、计划/实际/叠加张数、拼图配置。
  • <目标>_30s60_Astro_20261121-030840790_14C.fits：每张光帧；DATE-OBS 是曝光结束时刻（FITS 头注释已确认）。
  • 同名 .jpg 每帧预览 + Thumbnail\ 小图。
  • stacked.jpg：设备直出叠加成片。
  • 拼图会话另有 stacked-16_*.zip（16 位叠加）与面板内 img_stacked_all.tif。

导入时必须处理的三件事

  • failed_*.fits 是失败帧，不计入光帧与曝光。
  • 拼图会话要按「一个会话 = 一个夜次一个目标」聚合，面板只是子结构，不能算成多场拍摄。
  • 目标名是自由文本（实测有 IC 1805 160、NGC 6530 93、Unknown），需归一后再匹配天体库。

本轮整理范围

  • 纳入：Dwarf Mini 深空成片 + 机身原始帧（F:\Astronomy，只读接入）。
  • 纳入：银河成片、星轨成片。
  • 暂不纳入：佳能历史原始素材（量大且乱，后续再议）。

由此产生的两个特殊规则

  • “仅成品”的目标（银河、星轨）不显示自动累计曝光，改为可手工记录，并明确标注来源为手工。
  • 深空目标的自动识别以成片水印为主、以导出原始帧的 FITS 头为辅，两条路结果要能对得上。

03 · 现有方案调研（GitHub）

结论不变且更明确：没有现成开源软件能覆盖你的场景。它们都假设“有完整原始帧 + FITS 元数据”，而你手上最主要的入口是带水印的手机成片。

项目形态可借鉴的点关键差距
eg013ra1n/athenaeum~12 ★ · Rust + Tauri · Win/Mac/Linux 桌面应用 拍摄日历（中午到中午分夜）、目标库、器材库、按坐标聚类、重复检测、归档与导出 只认 FITS/XISF；不处理水印成片、不认银河与星轨；无天体科普；无中文
bartdelange/astro-library0 ★ · Python + React · Docker 自托管 Web 对象模型：目标 → 项目 → 夜次 → 文件；索引已有库；时间线；用 SIMBAD 补天体信息 极早期；需 Docker 常开主机；设备库仍在路线图；不做文件整理；无中英文别名与圈内俗称
yvinu/fits-manager-suite0 ★ · Python + SQLite NAS 服务 FITS 编目、项目与溯源 面向 NAS 运维，无桌面体验，不覆盖成片
Immich / PhotoPrism / LibrePhotos119.9k / 40.5k / 8.2k ★ 自托管相册 成熟相册、EXIF 检索、标签与时间线 通用照片逻辑：不懂天体、不懂单帧与累计曝光、不会读摄影水印
N.I.N.A. / nightwatch267 ★ / 98 ★ 采集控制 / 规划 拍摄自动化与今夜目标推荐 解决“拍什么”，不解决“拍完怎么存”
结论：自研一个轻量桌面应用是需求决定的，不是偏好问题。参考 astro-library 的对象模型与 athenaeum 的夜次/器材组织方式，但核心入口要换成“上传成片 → 读水印 → 归目标”。

04 · 范围

4.1最小完整旅程（P0）

  1. 建库：选一个空目录作归档根，软件建立「深空 / 星野」双主线结构。
  2. 导入成片：把手机里带水印的深空成片、银河/星轨成片、延时视频批量拖进来。
  3. 读水印识别：自动提取目标、日期、曝光，命中的直接归位，没把握的标黄待确认。
  4. 预览与执行：看整理计划，确认后按规则改名归位；可回滚。
  5. 看目标：深空目标详情页有统计、时间线、版本对比，以及一块「关于这个天体」的名片。
  6. 看星野：银河 / 星轨 / 延时三个页签，作品组配记录卡（地点、参数、时长、后期）。
  7. 增量：以后每次导出的深空原始帧、新拍的星野成片与视频，走同一套流程并入档案。

05 · 产品模型

中心对象仍是拍摄夜次。深空挂天体目标与天体名片，星野挂银河 / 星轨 / 延时子类与记录卡；夜次是两条主线唯一共享的维度，因此「夜次」单独作为一级浏览入口。

06 · 功能需求

6.1建库与导入

FR-01首次建库P0
入口
首次启动，或设置中的「新建档案库」。
处理规则
必须选择一个空目录作为归档根，软件在其下创建深空 / 星野双主线结构；目录非空时提示改用子目录，不覆盖任何已有内容。根路径记录在应用数据中，不写入照片目录。
结果
生成档案库与数据库，进入空状态首页，主区域只给一个主动作：「导入作品」。
异常
路径不可写、空间不足、只读盘 → 阻止建库并说明原因；不允许把归档根设成来源目录本身。
FR-02导入来源P0
方式
① 拖拽文件夹或多个文件到窗口；② 从手机相册导出到电脑后选文件夹；③ 选择 SD 卡/移动硬盘目录；④ P0 插上 Dwarf Mini 后直接选择盘符，只读 \Astronomy（结构见 02 节），自动识别为“原始帧目录”。
来源类型
Dwarf Mini 成片 / 相机成片 / 普通文件夹 / 原始帧目录（Dwarf 机身）。类型决定后续走水印识别还是读 FITS + shotsInfo.json。
排除规则
导入时可勾选“跳过非图片文件”“跳过小于 X KB 的缩略图”；本轮默认不扫描佳能历史原始素材，该来源需手动添加才会被处理。
只读
扫描阶段绝不修改来源文件；只有执行整理时才移动/复制。
异常
来源离线时保留记录并标记「不可访问」，已入库素材不受影响。

6.2识别（本产品的核心能力）

FR-03水印识别成片P0已用样本验证

Dwarf Mini 出图带一条底部白色信息条，黑字白底、无艺术字、不压星点——这是最理想的识别目标。它也是你最主要的导入入口，必须做成“拖进来就能认出是什么”。

实测样本（来自参考素材目录）

目标总曝光日期 / 时间画幅右侧附加信息
NGC 22641小时20分2026.11.22 06:272:3 竖构图DWARF mini · 30s · 60 · 天文
HD 378054小时2026.11.22 04:252:3 竖构图DWARF mini
M 455小时17分2026.10.07 05:431:1 方构图DWARF mini
M 423小时51分2026.11.21 09:191:1 方构图DWARF mini

信息条结构固定为：左侧第一行目标名、第二行“总曝光 | 日期 时间”；右侧设备标识与拍摄参数。四张样本画幅不同，但信息条始终贴底。

条带定位
不能按固定像素裁切。从图片底部向上扫描连续的高亮度、低方差行，定位白条上边界；因此 2:3、1:1、横构图都能处理。找不到白条则判定为“非 Dwarf 水印图”，走元数据或手工。
识别方式
在本地对白条做文字识别，提取目标、总曝光、日期、设备标识；照片不上传任何服务器。
字段解析
  • 第一行 → 目标原名（如 M 45、NGC 2264、HD 37805）。
  • 第二行按 | 切分 → 总曝光 + 日期时间；4小时、1小时20分 统一换算成分钟数。
  • 右侧出现 DWARF mini → 器材自动锁定为 Dwarf Mini。
  • 右下角 30s · 60 · 天文 可选解析为单帧曝光、帧数/增益、拍摄模式，解析不出则留空。
名称归一
去空格与全半角差异（M 45 → M45），统一 NGC/IC/HD/M 前缀；再与目标别名表匹配。样本中的 HD 37805 属于恒星编号，需支持“恒星类目标”，不能只认星云星系。
曝光来源
水印里的总曝光直接可用，解决“深空只有成片也能统计”的问题。标注来源为「水印」；若后续接入原始帧并与自动统计不一致，以原始帧为准并提示差异。
置信度
低置信度、多候选、文字残缺 → 整条标黄待确认，绝不静默归类；支持一键把整批设为同一目标。
模板学习
首个白条识别成功后，记住“白条高度比例 + 两行两列”的版式，同批图片直接套用，减少误差。
兜底
识别完全失败 → 待整理收件箱，由你手动指定目标；其余字段仍可自动读取。
结果
该成片获得目标、夜次、器材、总曝光，并进入整理计划预览。
时间语义（已确认）：水印上的日期时间是本次拍摄的结束时间。所以归档夜次不能直接用这个日期，必须换算：
  • 结束时间在 00:00–12:00 → 夜次归到前一天（前半夜那一天）。例：2026.11.21 09:19 → 夜次 2026-11-20。
  • 结束时间在 12:00–24:00（少见）→ 夜次记为当天，并标记「时间待核」。
  • 接入机身原始帧后，以每帧 DATE-OBS 的实际拍摄时间重新计算夜次；与成片换算结果不一致时提示，并支持按原始帧批量修正。
FR-04文件元数据识别P0
来源读取内容用途
FITS（Dwarf 原始帧）OBJECT DATE-OBS EXPTIME GAIN FILTER CAMERA FOCALLEN目标、夜次、单帧曝光、帧类型。DATE-OBS 是曝光结束时刻（头注释 Time end of exposure 已确认），首帧开始时间 = DATE-OBS − EXPTIME
shotsInfo.json（Dwarf 会话）目标名、RA/DEC、单帧曝光、增益、滤镜、CMOS 温度、计划/实拍/叠加张数、拼图配置整场拍摄的权威摘要；拼图会话靠它区分面板与整图
JPG / RAW（佳能成片）EXIF：DateTimeOriginal Model FocalLength ExposureTime ISO夜次、器材、焦距判定银河/星轨
导出成片（JPG/PNG/TIFF）EXIF 可能已被抹除优先按同目录关联或水印识别；都不行则进收件箱
未识别
缺少时间或设备 → 待整理收件箱，不阻塞其他文件。
时间异常
早于 2000 年或晚于当前时间 → 标记「时间可疑」，可一键修正整批。
FR-05目标归类与别名归一P0
深空
优先取水印识别结果；有 FITS 时用 OBJECT 或 RA/DEC 校验，两者不一致时提示你选择，不自动覆盖。
银河
星野子类。按“器材 + 焦距 ≤ 35mm”初判，再细分银心 / 夏季银河 / 银河拱桥 / 自定义。
星轨
星野子类：照片与视频同属一组；不做天体名片，用记录卡（FR-11A）。
延时
星野子类：一组可含视频成片与序列帧，抽首帧作封面；不做名片，字段见 FR-21。
同名归一
M 31、M31、NGC 224 归并为同一目标，保留全部别名；合并需确认且可撤销。
新目标
识别到库中没有的目标时，自动创建草稿目标，并尝试联网补全天体名片（见 FR-11）。

6.3整理计划与执行

FR-06生成整理计划P0
原则
扫描与识别完成后不立即动文件，先产出可审阅的计划。
内容
每条含：源路径 → 目标路径、判定依据（水印/EXIF/FITS/手工）、目标、器材、夜次、预计体积、冲突标记、置信度。
分组
按目标分组、组内按夜次展开；顶部汇总“将整理 N 个文件 / 共 X MB / 涉及 M 个目标”。
可编辑
执行前可改目标、夜次、器材、排除某条；改动实时重算目标路径。
保存
计划以草稿保存，可关软件后继续审阅。
FR-07冲突处理P0
冲突默认行为可选
目标位置已有相同内容不重复复制，标为「重复」，仅登记关联保留两份 / 只留一份
同名不同内容自动加序号后缀，绝不覆盖手动改名 / 跳过
同一图被多次导入按内容哈希合并为一条指定以哪次为准
目标归属不确定标黄，默认不执行人工指定后转可执行
禁止
不提供“全部覆盖”这类一键危险操作。
FR-08执行与校验P0
执行前
二次确认，列出文件数、总容量、是否跨盘。
执行中
逐文件进度与当前文件名；可暂停、可中止；中止后已完成部分有效，未完成留在原处并标记。
跨盘
先复制 → 校验大小与哈希 → 通过后才删除源；失败保留源并报错。
结果
写操作日志；完成汇总“成功 N / 失败 M / 跳过 K”；失败项可重试。
FR-09回滚P0
范围

行为

FR-20增量同步（连上机身，一键入库）P0v0.6 新增

Dwarf 机身容量有限、随时可能清空，所以「先拍、清机身、以后再归档」是常态。软件必须能以会话目录为单位做增量同步：成片你自己拖进来，原始素材点一次「同步」补齐，不用记哪一晚拷过、哪一晚没拷。

你的操作
① 把带水印的成片拖进软件（或丢进 _收件箱）；② USB 连上 Dwarf；③ 点顶部「同步」按钮。剩下的全自动。
自动检测
扫描 F:\Astronomy 下的会话目录、拼图面板与 CALI_FRAME 校准场，和素材库已有记录比对，只处理「没同步过」和「上次没拷完」的。校准场新增的会自动补进 _dwarf mini校准场\；DWARF_DARK 暗场库只保留首次拷贝，之后不参与自动同步。
只拷有用的
拷光帧 FITS + 会话里的 shotsInfo.json + stacked.jpg（作参考缩略图）；跳过 failed_*.fits，跳过每帧自带的 jpg 预览与 Thumbnail\ 小图（同一帧重复两份，无归档价值），跳过 Solving_Failed 诊断图。
自动归档
读 shotsInfo.json 的 target / exp / gain 与首帧 DATE-OBS − EXPTIME 换算夜次，直接落到 {目标}\{夜次}_{器材}\raw\；目标名归一（IC 1805 160 → IC1805），认不出的先放 _收件箱 并提示。
去重与断点
以「会话目录名 + 文件相对路径 + 文件大小」判断是否已存在；中途拔线、空间不足、关软件后再次点击，只补缺失文件，不重复拷、不重复统计。
空间预检
开始前算出本次待拷容量，剩余空间不够就先提示所需容量并禁止开始，绝不拷到一半撑爆。
写历史
每拷一个文件都写一行到 _历史记录\素材库历史记录.csv（见 7.6）；结束时汇总「本次新增 N 个文件 / M 个目标 / X GB」。
成片与原始帧配对
成片按水印里的目标 + 夜次自动挂到对应的 {目标}\{夜次}_*\final\；配不上时挂在目标层并提示「未找到对应原始帧」，不阻断入库。
可安全删除清单（可选）
同步结果页提供可勾选项「生成可安全删除清单」，不勾选就不生成。勾选后按会话输出一份清单（会话名、文件数、已校验状态），供你在设备端对照清理；软件绝不自动删除机身文件。
不做
不自动删除机身文件（清机身始终由你在设备端决定）；同步过程不联网，全程本地。
FR-21星野摄影（银河 / 星轨 / 延时）P0v0.7 新增

星野与深空是两条并列主线：文件形态、元数据与统计口径都不同，不能混进“目标库”。星野以广角成片和视频为主，几乎没有可读的原始帧，因此用记录卡代替天体名片。

07 · 共享规则

7.1归档结构（深空 / 星野双主线）

素材库固定放在 <素材库根目录>，只放素材，不放程序；软件本体放在 <项目目录>。一级只分深空与星野两条主线：深空下目标在最外层；星野下先分子类（银河 / 星轨 / 延时），再按夜次与器材。这样在资源管理器里翻也符合直觉：先想“深空还是星野”，再想“哪个目标 / 哪类作品”。

│   │   └── 2026-11-20_DWARFMINI\
│   │       └── final\
│   └── NGC7000_北美洲星云\
└── 星野\                          ← 主线二：广角
    ├── 银河\
    │   └── 2026-07-18_CANON15MM\

7.2曝光口径

  • 有原始帧：累计曝光 = Σ（单帧曝光秒 × 帧数），仅计 light 帧；校准帧、叠加中间文件、成品导出、failed_*.fits 不计。Dwarf 机身高 8,208 张可用光帧实测约 90.9 小时，可作为导入后的校验基准。
  • 深空仅有成片：直接采用水印中的总曝光，标注「来源：水印」；接入原始帧后以自动统计为准，并在两者不一致时提示差异，不静默覆盖。
  • 手工值最高优先：任何手工填写的曝光、日期、器材都覆盖自动结果，并标注「来源：手工」（见 FR-19）。
  • 星野（银河 / 星轨 / 延时）：不参与累计曝光统计；有 EXIF 时显示单张参数与总时长，视频显示时长，缺信息显示「—」；手工填“单张曝光 × 张数”只生成估算值并标注「手工记录」。
  • 相同内容文件只计一次；重新扫描不会重复累加。
  • 帧类型无法判定时显示「未计入」并给原因，不静默忽略。
  • 格式统一为「X 小时 Y 分钟」，小于 1 小时显示「Y 分钟」。

7.4联网与隐私

  • 联网只用于：拉取天体名片资料与公开图片、校准基础天体数据。
  • 请求内容仅含目标编号或名称，不上传照片、路径、个人信息。
  • 水印识别与元数据解析全部在本地完成；断网可用。
  • 所有外部图片与数据必须在界面标注来源；用户可手动替换与锁定，锁定后不被在线更新覆盖。

7.5不可逆操作

08 · 异常与边界

水印识别

  • 水印被裁掉 → 退回元数据与手工。
  • 水印压在星点上、对比度低 → 标待确认，不猜。
  • 同一张图有多个目标文字（如拼接图）→ 提示拆分为多个素材。

联网与资料

  • 断网 → 用缓存或内置基础字段，不显示空白页。
  • 图片源失效 → 保留文字，隐藏破图并提示「配图暂不可用」。
  • 目标冷门、查不到 → 显示编号与“暂无详细资料”，允许你补写。

磁盘与来源

  • 来源盘未插 → 标记离线，不丢记录。
  • 移动中拔出硬盘 → 中止当前文件，未校验的文件不计为成功。
  • 空间不足 → 执行前预检，不够则禁止开始并给出所需容量。

数据与规模

  • 数据库损坏 → 支持“重建索引”重新扫描归档根。
  • 卸载软件 → 照片与目录结构不受影响。
  • 单次 1 万文件以上 → 显示进度并可取消，界面不卡死。
  • 缩略图按需生成并缓存，不一次性全量生成。
